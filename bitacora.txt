MiniReto 9 — DevTools: propiedades heredadas vs no heredadas

Elemento inspeccionado: <p> dentro de <header> en index.html

Propiedad heredada: font-family
El <p> no tiene font-family declarado, pero muestra "Open Sans", sans-serif
porque lo hereda de body, donde se definió con var(--fuente-cuerpo).
En DevTools aparece como "Inherited from body".

Propiedad heredada: color
El <p> muestra #212121 heredado de body, donde se definió con var(--color-texto).

Propiedad no heredada: display
El <p> tiene display: block, pero viene del user agent stylesheet (estilos
por defecto del navegador), no del padre. No dice "Inherited from".


MiniReto 10 — Conflicto de especificidad

Selectores en conflicto:
  #menu a       → especificidad (1, 0, 1) — un ID + un elemento
  .activo       → especificidad (0, 1, 0) — una clase

Problema: #menu a tiene mayor especificidad que .activo, por eso el color
de .activo aparecía tachado en DevTools y no se aplicaba. El enlace activo
seguía mostrando el color de #menu a (#212121) en vez del verde (#2E7D32).

Solución: cambiar el selector a #menu a.activo, que tiene especificidad
(1, 1, 1) — un ID + una clase + un elemento. Así le gana a #menu a sin
necesidad de usar !important ni estilos en línea.


MiniReto 11 — Box model: medición de tarjeta con box-sizing

Elemento medido: .tarjeta (primer servicio en index.html)

Sin border-box (content-box, valor por defecto):
  width declarado: no tiene (ocupa el 100% del padre)
  padding: 1rem (16px por lado)
  border: 1px por lado
  Ancho total = ancho del contenido + 32px de padding + 2px de borde
  El elemento se desborda si el padre ya ocupa todo el ancho disponible.

Con border-box:
  El padding y el borde se incluyen DENTRO del ancho declarado.
  Ancho total = el ancho que le asignás, sin sorpresas.
  No se desborda.

Conclusión: border-box es más predecible para maquetar. Por eso se aplica
con *, *::before, *::after { box-sizing: border-box; } a todos los elementos.


MiniReto 12 — Posicionamiento y lanzamiento v1.0

Etiqueta "Nuevo":
  Se usa position: relative en la tarjeta para convertirla en punto de
  referencia. Luego position: absolute en la etiqueta para anclarla a la
  esquina superior derecha (top + right) sin desplazar el contenido.

WhatsApp flotante:
  Se usa position: fixed para que el enlace quede anclado a la ventana
  del navegador (bottom + right), no al documento. Así se ve siempre
  visible al hacer scroll.

Los tres tipos de position usados:
  relative — el elemento se queda en su lugar pero sirve de referencia
  absolute — sale del flujo y se posiciona respecto a su padre relative
  fixed — sale del flujo y se posiciona respecto a la ventana

Verificación DevTools — Columnas de la flota en modo dispositivo:
  La flota usa grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)),
  por lo que el número de columnas depende del ancho disponible:

Cambios mobile-first aplicados:

    con padding y font-size normales
  - 1200px (escritorio): portada con min-height: 60vh

Enfoque: se escribió primero el CSS para la pantalla más chica y se fueron
sumando reglas con min-width para pantallas más grandes. Esto es mobile-first:
el diseño base es el móvil y se expande, en vez de escribir para escritorio
y reducir con max-width.


Semana 2 — Día 2

MR5 — La flota en Bootstrap: primera comparación

Archivo: pruebas/catalogo-bootstrap.html

Distribución con la grilla de Bootstrap (col-12 col-sm-6 col-lg-4 col-xl-3):
  < 576px (base):  1 columna  → col-12 (ocupa las 12 de 12)
  >= 576px (sm):   2 columnas → col-sm-6 (ocupa 6 de 12)
  >= 992px (lg):   3 columnas → col-lg-4 (ocupa 4 de 12)
  >= 1200px (xl):  4 columnas → col-xl-3 (ocupa 3 de 12)

Comparativa CSS propio vs Bootstrap:
  CSS propio (v1.5):
    - La flota usaba grid-template-columns: repeat(auto-fit, minmax(250px, 1fr))
    - Responsive "automático" por auto-fit, pero sin control preciso de los
      breakpoints (el navegador decide cuántas columnas caben)
    - ~8 líneas de CSS para la distribución (.flota + media queries)

  Bootstrap:
    - Distribución resuelta con clases en el HTML: col-12, col-sm-6, col-lg-4, col-xl-3
    - 0 líneas de CSS de distribución (todo en clases utilitarias)
    - Control exacto de cuántas columnas en cada breakpoint
    - Los gutters (g-4) reemplazan el gap de CSS Grid

  Qué da Bootstrap sin esfuerzo: breakpoints predefinidos, gutters, container
  centrado con max-width automático, sistema de 12 columnas consistente.

  Qué control se pierde: el auto-fit de CSS Grid se adaptaba solo a cualquier
  ancho sin definir breakpoints; con Bootstrap hay que elegir explícitamente
  cuántas columnas en cada breakpoint.

  Conclusión: Bootstrap es más rápido para armar layouts conocidos (1-2-3-4
  columnas), pero CSS Grid con auto-fit es más flexible cuando no sabés de
  antemano cuántas columnas querés.


MR6 — Sin una línea de CSS: utilidades

Archivo: pruebas/catalogo-bootstrap.html (sección "¿Por qué Rueda Libre?" + banner CTA)

Regla: cero <style>, cero style="", cero clases propias. Todo resuelto con
clases utilitarias de Bootstrap.

5 clases utilitarias encontradas en la documentación de Bootstrap:

  1. text-bg-{color} (ej. text-bg-success)
     Atajo de componente que aplica background-color Y color de texto con
     contraste accesible en una sola clase. Docs: Color & background.

  2. object-fit-cover
     Equivalente a object-fit: cover en CSS. Hace que una imagen llene su
     contenedor recortando en vez de deformarse. Docs: Object fit.

  3. gap-{size} (ej. gap-3)
     Aplica la propiedad CSS gap a contenedores flex o grid. Reemplaza los
     márgenes manuales entre hijos. Docs: Gap.

  4. lead
     Clase de tipografía que agranda y aliviana un párrafo para destacarlo
     como subtítulo o introducción. Aplica font-size: 1.25rem y
     font-weight: 300. Docs: Typography.

  5. d-none / d-{breakpoint}-block (ej. d-none d-md-block)
     Oculta un elemento por defecto y lo muestra a partir de un breakpoint.
     Útil para elementos decorativos que no caben en móvil. Docs: Display.

Estructura de la sección de beneficios:
  - 4 columnas (col-12 col-sm-6 col-lg-3): 1 → 2 → 4 columnas
  - Cada beneficio: emoji decorativo (fs-1), título (fs-5 fw-bold), párrafo
    descriptivo (text-secondary), dato destacado (fw-bold text-success)
  - Todo centrado con text-center y espaciado con p-3

Estructura del banner CTA:
  - Fondo verde con text-bg-success, padding vertical con py-4
  - Contenido en flex: columna en móvil (flex-column), fila desde md
    (flex-md-row) con justify-content-between y align-items-center
  - Imagen decorativa oculta en móvil (d-none d-md-block)
  - Botón con text-bg-dark, rounded-3, padding horizontal/vertical (px-4 py-2)
  - gap-3 separa los elementos sin necesidad de márgenes individuales

Conclusión: las utilidades de Bootstrap permiten armar secciones completas sin
escribir una sola línea de CSS. El HTML queda más largo (más clases), pero la
ventaja es que no hay un archivo CSS separado que mantener ni conflictos de
especificidad. El tradeoff es legibilidad del markup vs simplicidad del estilo.

3 conflictos encontrados en DevTools:

  Conflicto 1 — body margin
    Bootstrap (reboot.css): body { margin: 0 }
    style.css (antes): body { margin: 0 }
    En DevTools aparecían ambas reglas. Como hacen lo mismo, se eliminó la de
    style.css. Bootstrap gana igualmente porque su selector tiene la misma
    especificidad y se carga primero, pero la de style.css era redundante.

  Conflicto 2 — box-sizing reset
    Bootstrap (reboot.css): *, *::before, *::after { box-sizing: border-box }
    style.css (antes): *, *::before, *::after { box-sizing: border-box }
    Exactamente la misma regla duplicada. Se eliminó de style.css porque
    Bootstrap ya la declara. En DevTools la de style.css ganaba por orden de
    carga (último gana con misma especificidad), pero el resultado era idéntico.

  Conflicto 3 — gap en el menú de navegación
    Bootstrap: .d-flex no declara gap (se necesita la clase gap-*)
    style.css (antes): #menu { display: flex; gap: 2rem }
    Al migrar #menu a d-flex con gap-4 (1.5rem de Bootstrap), el gap de 2rem
    de style.css ganaba por especificidad del ID. Se eliminó la regla de layout
    de #menu del CSS y se dejó gap-4 en el HTML. Si se quiere exactamente 2rem,
    se podría usar una clase gap custom, pero 1.5rem (gap-4) es visualmente
    equivalente.

Comparativa final CSS propio (v1.5) vs Bootstrap (v2.0-beta):

  Líneas de CSS:
    v1.5: ~200 líneas (distribución + identidad + 2 media queries)
    v2.0-beta: ~130 líneas (solo identidad, 0 media queries)
    Reducción: ~35% menos CSS

  Tiempo de desarrollo:
    v1.5: cada sección requería escribir display, grid-template-columns,
    flex-direction, gap, max-width, margin, y luego duplicar todo en media queries
    v2.0-beta: las clases de Bootstrap resuelven distribución en el HTML;
    no se escribió ni una sola media query

  Ventajas de Bootstrap:
    - 0 media queries propias (todo resuelto con col-{bp}-{n} y flex-{bp}-{dir})
    - Tablas responsive gratis con table-responsive (scroll horizontal en móvil)
    - Container centrado con max-width automático por breakpoint
    - Consistencia: todos los breakpoints y spacing siguen la misma escala
    - Menos conflictos de especificidad al no duplicar reglas de layout

  Ventajas de CSS propio:
    - HTML más limpio (menos clases por elemento)
    - auto-fit en CSS Grid se adapta a cualquier ancho sin definir breakpoints
    - Sin dependencia de CDN externo (~200KB de Bootstrap)
    - Control total sobre cada valor (no limitado a la escala de Bootstrap)
    - Menor peso de página si solo se usan pocas reglas

  Conclusión: para un sitio de este tamaño, Bootstrap acelera el desarrollo y
  elimina la necesidad de escribir media queries, pero agrega ~200KB de CSS que
  mayormente no se usa. En proyectos más grandes con muchos componentes y varias
  personas en el equipo, Bootstrap (o Tailwind) paga la inversión porque todos
  hablan el mismo sistema de clases. Para un sitio pequeño personal, CSS propio
  puede ser más eficiente en peso final.
